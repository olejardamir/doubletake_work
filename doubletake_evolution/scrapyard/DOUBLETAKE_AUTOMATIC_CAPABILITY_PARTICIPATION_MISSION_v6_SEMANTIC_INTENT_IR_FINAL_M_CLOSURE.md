## Deficiency and proposed distinct mechanism

Criterion **M**: removing an internal capability name from a genuinely equivalent request must not cause appropriate *real* capability participation to disappear. Historical executable `collective_core/test_capability_nameless_reach.py::test_m_is_not_satisfied` and convergence table recorded **M OPEN**. Acceptance is `lost_due_solely_to_name_removal == []` on governed held-out and fresh cases, **not** a relaxed percentage. Historical zero-useful-token-overlap examples (worker/subordinate agent, remembered/stored memory, link/outbound relay, doubled-up/redundancy, single point/failure path) are diagnostic, never hardcoded synonym rules or target labels. Lexical thresholds, raw embedding cuts and probe-fitting failed to separate true semantic needs from unrelated criterion-G coincidence cases. Retrieval gain alone cannot fix downstream relevance/refusal losses.

**v6.1 hypothesis:** only the *already selected and running* OpenCode LLM compiles the current request into a de-identified, closed **Semantic Intent IR**. A pure deterministic DT matcher compares typed atoms against versioned, digest-bound capability profiles; the canonical router receives explicit candidate-specific **semantic admission evidence**. The LLM cannot select capabilities, rank/tie-break, grant permission, bind arguments, resolve conflicts, order execution, register capabilities or bypass governance. This is **not** a paraphrase appended to legacy lexical text, cosine score, second router, auxiliary embedding model or autonomous execution grant. Scope first to direct task-begin intent; other trigger types remain governed by existing behavior.

## Ten audited v6 integration pitfalls (dated source claims)

1. A top-level `CapabilityContract.semantic_profile` can be dropped by multiple `CapabilityContract.make()` reconstruction paths. Store a **typed validated** profile under digest-covered `effects["semantic_profile"]`.
2. `capability_semantic._semantic_effect_entries()` may serialize `effects` into legacy lexical/embedding text. Exclude `semantic_profile` **before** profile creation; changing profiles must change profile/contract digests **without** changing legacy lexical fingerprint or text.
3. Seed and `@auto_capability` declaration publishers skip existing persisted contracts; profile publication requires explicit **idempotent migration**.
4. `CapabilityAuthority.merge()` can lose omitted identity/evidence fields. Use a profile-only setter with `dataclasses.replace(contract,effects=updated,digest="")` or an equivalent proven clone; preserve `registered_at`, evidence, status, description, provenance, intents, bindings, examples, requirements, safety, execution mode, fidelity and verification; atomic persist, revision change only on actual content change.
5. `CapabilitySemanticIndex(authority)` may instantiate a local embedding provider. Automatic participation needs explicit `use_embedding_provider=False` while preserving fingerprint behavior and unrelated consumers' defaults; `isolate=True` is **not** equivalent. Test with `DOUBLETAKE_EMBEDDING_MODEL` set and provider resolver patched to throw.
6. `project_evolution.boundary.submit_user_prompt()` historically runs participation before `/api/chat` resolves actual provider/model and OpenCode readiness; semantic compilation must happen **later**, after final model selection.
7. `ParticipationSession.participate()` historically executes immediately on lexical MATCH. Nameless task-begin must **defer provisional execution**, resolve semantic evidence, then execute at most once in the **same** round.
8. `OpenCodeProvider.complete_structured()` is plan-schema-specific and may salvage text/JSON; unsuitable for strict Semantic Intent IR.
9. Legacy `opencode_compat.prompt_from_legacy()` / `_post_message()` may drop native `tools` and `format`. Use a dedicated native-v2 request or explicitly tested field-preserving translation.
10. Adapter transport identity `opencode` differs from the actual selected `{providerID,modelID,variant}`. Bind semantic call and returned response to the **final reconciled** immutable model reference; reject mismatch.

These are **historical** audits, not verified defects in present DT.

## Proposed bounded flow and authority

```text
direct task-begin -> canonical deterministic route/preflight
  full normalized canonical capability name -> existing zero-LLM execution
  nameless request -> one bounded PendingSemanticRound, no provisional execution
    -> runtime resolves actual active OpenCode model and service
    -> unavailable/non-OpenCode: freshly revalidate deterministic route and fallback
    -> active OpenCode: isolated native JSON-schema compiler call #1
    -> independently validate IR, request/vocabulary/profile/model/session digests
    -> resolved IR -> deterministic structural matcher -> candidate-specific evidence
    -> existing router + unchanged permission/safety/binding/composition gates
    -> optional measured call #2 for genuine ambiguity (never more than 2)
    -> finalize original round, execute at most once, clear pending state
```

**Named fast path** requires full ordered canonical name normalized across case/hyphen/underscore/space; partial components and hand-built aliases do not qualify. It decides **cost/ordering**, not relevance. One canonical preflight/router owner, no duplicate router. Pending round binds original intent/trigger/context/arguments, raw-route/request digest, authority revision, inventory/profile digest and round index. No fabricated second `task_begin`, no extra reevaluation round, no pending `invoked`/contribution success; clear on success, failure, cancellation, fallback and disposal. Revalidate current contract/authority before execution; reject stale profile/vocabulary evidence, bounded fallback instead of recompile loop. Main request remains authoritative; semantic IR does not invent execution arguments.

**Hypothesized implementation map (verify current DT):** `collective_core/capability_contract/{_models,_authority,_seeds}.py` and `capability_declaration.py` (profile and field-preserving reconciliation); `collective_core/capability_semantic.py` (lexical isolation and no-embedding participation factory); pure provider-free `collective_core/capability_semantic_ir.py` (typed atom/profile/vocabulary/IR/evidence/matcher); `capability_router.py` (typed candidate-specific semantic admission, deterministic gates); `capability_participation.py` (preflight/pending/same-round finalization); `providers/opencode_provider.py` (isolated native structured transport); `project_evolution/boundary.py` (preserve session); `api/chat_sse/chat_route.py` (after actual model/readiness, before main prompt); CLI/self-upgrade/direct ingress via **one** shared runtime bridge or deterministic fallback. Do not place provider calls in `rank_candidates`, `CapabilityRouter.route`, `_drop_coincidental_matches`, `_admit_set_members`, `bind_arguments` or `execute_composed_plan`. `ParticipationSession` stores no provider object. No new provider router or service startup for semantic rescue.

## Profile, IR, matching and negative controls

- **Profiles:** closed schema v1 under `effects["semantic_profile"]`, dimensions `operations`, `subjects`, `properties`, `outputs`; atom identity **(dimension, atom_id)**, with machine-safe ID and short explanatory gloss. Illustrative atoms `operation:inspect`, `subject:outbound_communication_path`, `property:redundancy`, `output:status` are *not* production aliases. Derive from capability implementations, declarations and seeds, not held-out requests. A persisted old-style contract must migrate idempotently with all unrelated fields unchanged and reload successful.
- **Vocabulary:** deterministic sorted union of currently routable profiles, dimension+atom+normalized-gloss digest, reject conflicting definitions for same dimension/ID, deduplicate identical definitions. Call #1 sees only dimension→atom/gloss, **no capability names/IDs/bindings/paths or which atoms belong to a capability**. Inventory changes change digest; old IR becomes stale.
- **IR:** closed `schema_version=1`, `status=resolved|partial|unresolved`, bounded operation/subject/property/output IDs and typed `negated` atoms. Reject unknown/duplicate/oversized/foreign-dimension atoms, extra fields, capability identifiers, rank/winner, reasoning, tools or executable instructions. Only `resolved` may rescue admission; partial/unresolved -> freshly revalidated deterministic fallback. Preserve negation; absent property is not a contradiction.
- **Matcher:** deterministic structural set/logic, no learned threshold; require at least compatible **operation AND subject**, and compatible property/output when relevant. One generic atom alone is insufficient; explicit contradictions exclude candidate. Typed immutable `SemanticCapabilityMatch` binds contract/profile/IR digests. A validated candidate may bypass only **lexical retrieval absence, lexical similarity minimum, lexical coincidence refusal**; never contract existence/digest, routability, source/fidelity, safety, input binding, composition/conflicts/exclusive resources, duplicate/already-participated controls, distrust/recovery, permissions or budgets. Merge duplicate lexical/semantic candidates once; no fabricated cosine score or model ranking.
- **Future capability:** a new declaration introduces new atoms, updates vocabulary and participates on an independently phrased request **without central synonym or routing edits**. This is an essential anti-probe-fitting proof. Conflicting glosses cause semantic unavailability, not arbitrary definition choice.

## Native OpenCode-only compiler and failure behavior

**Only learned system:** the already-connected selected OpenCode model. No auxiliary downloads or local cache fallback: `SentenceTransformer`, `from_pretrained`, Hugging Face, MiniLM/BGE/E5/GGUF/ONNX, `DOUBLETAKE_EMBEDDING_MODEL`, `get_models()` to choose another model, best-of-N, provider switch. Historical M tests reportedly instantiated MiniLM directly; retire model-download-capable active M certifiers only after current-source check, preserving archival negative evidence. Do not falsely prohibit unrelated embedding systems elsewhere.

**Native-v2 call #1:** fresh isolated semantic session on **existing** OpenCode service; exact final `model:{providerID,modelID}`; `tools:{"*":false}` to deny ordinary tools; `format:{type:"json_schema",schema:...}`; system compiler protocol; `parts:[{type:"text",text:canonical_JSON({current_request,vocabulary})}]`. Treat user text and profile glosses as untrusted **data**, not system instructions. Native structured object only, never scrape prose or markdown JSON; validate again in DT. No previous conversation, memory, tools, subagents, environment secrets, main-session mutation, raw sensitive response logs or recursive participation. Delete semantic session in `finally`; cancellation must not allow a late result to execute. Verify response's actual providerID/modelID (variant when reliable) and no ordinary tool event.

**Budget:** named=0 semantic calls; ordinary nameless=1; second call **only** if measured structural ambiguity remains, max=2 per intent. Optional #2 sees original request, validated IR and a small bounded set of anonymous candidate profiles C1/C2..., never canonical names, IDs, bindings or expected winner; returns only typed `supports|contradicts|uncertain`, no selection. Malformed/uncertain/excess candidates -> deterministic fallback, no third call. Reuse prior IR only with unchanged request, vocabulary/profile digests and schema. Explicit bounded failure statuses distinguish unavailable, timeout, wrong model, schema/unknown atom, partial/unresolved, stale inventory, optional adjudication failure and deterministic fallback. No unbounded retries or provider fallback.
