## Reusable mechanisms
1. **One governed lifecycle:** receive, classify, build provenance-tagged context, specify semantic intent, plan, gate permissions/value/risk, execute, observe, validate, independently critique, then promote, repair, rollback or reject. Only durable orchestration state may authorize transitions; model output is a proposal. Restart must preserve accepted state, evidence and idempotent effects.
2. **Least-complex adequate pattern:** deterministic logic → inexpensive classification → single ReAct agent → deeper reasoning → sequential/parallel specialists → coordinator/hierarchy → exceptional swarm. Choose by task predictability, dependency, cost, latency, risk, reversibility and measured quality. Do not create permanent agents for prompt-only roles. Parallel work needs independent scopes and explicit merge/conflict policy; hierarchy needs depth and leaf bounds.
3. **Tiered L0–L3 routing:** L0 schema/Git/test/deterministic checks; L1 cheap classifier; L2 normal reasoning; L3 expensive escalation. Record route, cost, latency, fallback and quality. All primary/fallback/repair outputs pass the **same validator** and authorization threshold.
4. **Bounded execution:** ReAct and repair require max steps, model/tool calls, wall-clock, cost, repeated-action/no-progress detection, stop/rollback/escalation conditions. A model saying “done” never proves effect. Typed events and idempotent consumers support concurrency without a redundant event bus.
5. **Context engineering:** construct each step from goal, accepted semantic spec, current tool observations, policy, relevant evidence, tools, remaining budget and acceptance. Track source/version/freshness/trust. Historical authority ordering: hard runtime truth > accepted spec > repository/tool observation > accepted memory > external evidence > model inference > raw candidate. Compression retains IDs, provenance, constraints, contradictions and retrieval pointers; external text never grants privileges.
6. **Semantic-first change and registry:** define behavior, overlap, owner, invariants, risks, input/output, failures and acceptance before code. One owner per lifecycle, state, capability registry, validation and promotion. Tool registry declares ID/schema/effects/permissions/risk/reversibility/idempotency/timeout/cost/callers/states/evidence. Runtime checks model-requested tools; MCP access is bounded, auditable and reuses existing capabilities.
7. **Memory, evidence and promotion:** validated memory retains negative results and rejection reasons; evidence ledger binds source revision, decision, tests, side effects and outcome. Independent critique and deterministic tests precede a single atomic promotion transaction; rollback/replay must not duplicate effects. Harvest/discovery produces untrusted proposals, never direct code authority. Replace obsolete owner paths rather than accumulating shadow subsystems; UI shows goal, status, evidence, approval and recovery without exposing internal orchestration.
8. **Security and economy:** least privilege, scoped approvals bound to exact artifact revision, deterministic checks where possible, budgets and meaningful action traces (not hidden model reasoning). New framework or agent count must beat simpler baseline in held-out quality/reliability per cost.

## Negative tests / definition of done
- Deterministic request remains L0; difficult task escalates with reason; compare against single-agent baseline on quality, latency and cost.
- Force primary-model timeout; invalid fallback is rejected by unchanged validator and permission gate.
- Crash after plan, tool effect, validation, pre/post promotion; replay yields exactly one authorized effect and coherent durable state.
- Inject external text requesting higher authority; stale approval, changed source revision and duplicated event fail closed. Compression retains conflict and provenance.
- Force repeated repair failure; budget terminates with recorded diagnosis/rollback. Seed a defect that independent critic must catch.
- Parallel conflicting updates obey merge policy; hierarchy and swarm show measurable benefit or remain disabled.
- Harvest candidate alone cannot modify implementation; accepted integration has real caller, negative tests, independent effect readback and removal/justification of replaced path.
