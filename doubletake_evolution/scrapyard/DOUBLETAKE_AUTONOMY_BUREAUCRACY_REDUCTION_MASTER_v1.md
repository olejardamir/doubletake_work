## Scope and decision principle

Desired bounded critical path for *already authorized* operations: intent → smallest durable task → one deterministic permission/risk check → execute → affected tests/verification → atomic activate or rollback → compact result → next independent task. Reduce duplicated human interruptions, gate count, redundant stores, repeated reports and latency **only with matched before/after measurements**. Standing grants are scoped to principal/effect/target/resources/expiry/revocation; an agent cannot issue or widen its own grant, change its safety policy, or retroactively approve protected history. Human/external/legal approvals remain when actually required. L0 independence, L1/FIC/validator, L2 spec-only, tool/network/secret boundaries and host workload guard remain enforceable. No new kernel, global dispatcher, parallel authority, privileged worker or unguarded experiment.

**Source-map before changes:** Trace request entrypoint → canonical owner/state/policy → decision → side effect → evidence write → next dispatch. Compare actual callers/writers for `mission_management/{models.py,store.py}`, governed-ingestion `mission_state.py`, `closure_dispatch.py`, `closure_queue.py`, `closure_acceptance.py`, human-review, promotion/release resolver, repair, tool gateway, scheduler and evidence. These are *historical paths*, not verified current owners. Record per mechanism: path, real caller, failure prevented, external obligation, overlapping enforcement, runtime cost, authority, KEEP/MERGE/AUTOMATE/LAZY/REMOVE and negative tests. A document or test-only helper is not a live owner.

## Six historically proposed bounded mechanisms and falsifiers

1. **T1 single durable task/dispatch owner:** Reuse an existing mission manager; compatible specialized dispatchers may adapt but cannot independently claim, retry or settle the same task. Require idempotent identity, restart recovery, parallel-claim safety, changed-input invalidation, exact terminal states and two-identical-no-progress parking. **Fail if** duplicate execution, competing authority, lost acknowledged state or stalled independent work. Tests: real entrypoint, crash/restart, concurrency, replay and blocked-task continuation.
2. **T2 delegated standing grants:** At existing gateway enforce effect classes (read, artifact, code mutation, network, destructive, external), principal, destination/target, scope, expiry, resource ceiling and revocation at initial action, retry, scheduling and promotion. Authorized routine tasks should not require per-task approval; missing/expired/forged/cross-user/aliased grants must fail before effects. **Fail if** self-evolution broadens permission or a report/approval record mints authority. Preserve legally required third-party review.
3. **T3 objective technical acceptance:** Use independent executable tests, source provenance, existing policy/FIC and release-owner activation/rollback for eligible internally delegated changes; derive redundant review views from one canonical receipt. **Fail if** stale/forged results, self-approved policy change, missing required FIC, wrong privilege, incompatible release or silent promotion of historically pending approvals. Acceptance of a synthetic research fixture is not enterprise/production approval.
4. **T4 evidence dependency minimization:** Map source/contract/test/evidence/release inputs; reuse verified unaffected evidence by exact dependency digest. Avoid report-only HEAD changes causing whole-mission rebind cascades *unless a current binding contract genuinely requires it*; change such contracts only by authorized migration. **Fail if** tampering or changed security input goes unnoticed, or unchanged inputs repeatedly regenerate commits. Historical evidence is not erasable.
5. **T5 bounded autonomous repair:** Reuse existing fault/diagnostic/release owners, keep last-good version, allow only bounded grant-covered repair, rerun affected tests, rollback on unsafe result, park repeated identical failures and continue unrelated work. **Fail if** resource-limit refusal is retried, orphan effects persist, duplicate external landing occurs, release pointer corrupts or protected policy is rewritten.
6. **T6 minimal truthful status and compatibility:** Derive one view of task, owner, latest verified digest, effect scope, tests, active version, blocker and next runnable action. Migrate readers before retiring duplicate stores/docs; preserve required audit/release history and `AGENTS.md` live rules. Measure distinct authoritative stores, active gate count, operator interventions, latency and redundant report commits; deletion count alone is not benefit.
