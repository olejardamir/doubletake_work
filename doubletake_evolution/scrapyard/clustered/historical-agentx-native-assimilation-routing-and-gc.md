## Classification, contract, strategy and fidelity

**Classification before executable generation:** Distinguish executable source, algorithm/procedure, API/interface spec, configuration, schema/data model, knowledge/design documents, tests, examples, changelog/history, agent instructions, build/packaging metadata, generated artifacts, binary/unsupported and unknown. README, LICENSE, AGENTS, books/papers, history, tests, data, configs, caches and metadata are **not whole-file tools by default**. Preserve provenance, source digest and classification reason; only a separately extracted behavior with useful intent, defined input/output, dependencies, side effects, permissions and tests can become a candidate. Untrusted source instructions must never enter system prompts or unsanitized live tool descriptions; retain quarantine/secret controls.

**One logical identity and typed contract:** Stable ID, version, name/description, semantic intents/aliases/examples, real input names/types/requiredness/defaults, output schema, pre/postconditions, side effects, permissions, implementation kind/ref, provenance, fidelity/quality/reliability, status, fallback/supersession. Unknown types remain unknown, never falsely all-string `value`. Use existing canonical authority and backwards-compatible migration; native, adopted, synthesized, wrapped/ported and core tools resolve through the same identity. Registry, Components DB, adoption binding, generated manifest, semantic index, MCP and execution backend are *views* or supporting stores, not competing routability owners. Preserve existing append-only/digest formats; versioned companion keyed by canonical `cap_id` is preferable to destructive schema change. States must distinguish `KNOWLEDGE_ONLY`, candidate/implementing, fidelity-rejected, routable, quarantined, superseded, rejected and fully assimilated. One prompt names legacy registry as presumptive owner; the later baseline-specific prompt names `CapabilityAuthority`; current owner is **UNKNOWN**.

**Before writing code:** derive stable behavior identity, compare exact digest and semantic contract, classify `IDENTICAL/EQUIVALENT/OVERLAPPING/COMPLEMENTARY/NEW`; merge equivalent provenance rather than generating numbered `_2` modules. One source may yield zero/many capabilities, several sources one capability. Select exactly one `ADOPT_SOURCE`, `WRAP_SOURCE`, `PORT_SOURCE`, `REIMPLEMENT_FROM_SPEC`, `SYNTHESIZE_FROM_KNOWLEDGE`, `KNOWLEDGE_ONLY` or `REJECT`; consider license, dependencies, isolation, maintainability, existing equivalents and fidelity. Never silently import foreign code outside governed adoption.

**Fidelity gate:** Prefer original source tests → differential original-vs-adopted results → golden fixtures → invariants/properties → contract tests; generated tests are supplementary. Placeholder/echo/canned success/metadata-only or silently omitted central behavior is `PLACEHOLDER/FAILED/UNKNOWN`, not routable. A `PARTIAL` subset must be explicit, unsupported behaviors excluded. Preserve source→implementation→test evidence, signed/traceable digest as available, failure reasons, and quarantine of rejected generated code. Test deliberate fake wrapper rejection.

## Retrieval, ordinary-request routing, execution and telemetry

**Reuse existing seams** (historical candidates; locate current equivalents): `tools/agentx_evolve/collective_core/{capabilities,service,components_db,adoption,supersession,assimilation_queue,capability_contract,executor,agentx_mcp_server}.py`; `tools/agentx_evolve/collective_synthesized/tool_runtime.py`; `tools/agentx_evolve/semantic/{service,semantic_index}.py`. Do not add parallel vector store, registry, runtime, governance, executor or unbounded planner.

**Capability index:** Existing `SemanticService` indexes compact sanitized canonical contract text (name, intents, aliases, description, inputs/outputs, effects and requirements) under executable `capability_contract` scope, **not raw documents**. On add/update/retire/supersede/non-routable transition, revision-bound index update or deactivate; idempotent replay. Separate knowledge vs executable retrieval. A bounded deterministic lexical/structured fallback on name/intents/aliases/schema must work safely when embeddings unavailable; no false semantic success. `search_capabilities(need_text, top_k=8, constraints=None)` is an example, not a new required API.

**Router:** Wire the actual normal reasoning caller, not just debug API. `route_capabilities(task_text, context, constraints)` retrieves small top-K, filters inactive, unverified, permission-/schema-/precondition-incompatible, ranks explainably by semantic/lexical fit, fidelity, I/O, reliability, side effects, latency/cost, supersession; deterministic ties. Competing implementations may win under offline/latency/accuracy/no-side-effect constraints. Return explicit `NO_MATCH` for unrelated intent; never force nearest irrelevant tool. For short composition, default ≤4 acyclic steps with compatible output→input mappings, typed inputs, expected postconditions and permission checks. Reject cycles and unresolvable dependencies.

**Argument binding:** User/task/context/previous step outputs → validated canonical schema; do not invent missing required inputs. Return `READY`, `MISSING_REQUIRED_INPUT`, `AMBIGUOUS_INPUT`, `INVALID_INPUT`, or `PERMISSION_REQUIRED`. User may supply missing task data but should never need to identify the source/tool name.

**One governed executor:** Canonical ID+validated args dispatches existing native/adopted/synthesized/wrapped/ported backends under current policy, approvals, isolation and effects. Verification receipt includes route ID, cap ID/version/implementation digest, input/result digest, execution and postcondition status, failure class, fallback, time/latency when known. A function returning without exception is not proof of postconditions. On failure: classify, persist telemetry, avoid repeating identical route, try next safe ranked alternative with bounded retries, or stop. Track attempts, verified successes/failures, argument/postcondition failures, latency, recent success and failure classes; reliability is a secondary signal, not a popularity override.

**Bounded model/MCP exposure:** Normal `tools/list` must not append every `synth_<name>` definition. Prefer one generic intent executor (historical example `borg_execute_intent`) or small task-scoped top-N schemas. Preserve `synth_call`, `synth_list` and operator/debug per-module access behind explicit mode. Schema must come from canonical contracts. With **100** additional fixture capabilities, normal MCP tool count stays essentially constant while correct intent remains routable. No tool-context explosion.

## Atomic publication, migration and cleanup

**One logical hot transaction:** Stage/classify/extract/fidelity-test/contract/runtime package; publish canonical authority, implementation binding, semantic record or lexical fallback metadata, routing visibility, relevant manifest/adoption view; only then mark `FULLY_ASSIMILATED`. On any failure, roll back/unpublish all new live views and generated artifacts, keep original source/evidence, leave explicit non-routable failure. Use authority revision/invalidation for caches. The *next ordinary reasoning cycle in the same process* must discover/execute the new capability without restart, MCP reconnect or manual refresh.

**Historical inventory migration:** Only after admission, authority, fidelity, routing and publication work, scan generated modules, `mcp_tools.manifest.json`, legacy registry, authority, semantic records and staging. Classify `KEEP_EXECUTABLE`, `REBUILD_EXECUTABLE`, `KEEP_AS_KNOWLEDGE`, `RETIRE`, `DELETE_GENERATED_ARTIFACT`. Produce deterministic dry-run item/action/reason/owner/affected references before mutation. Distinguish generated owner files from original imported source; never delete user/external originals, active canonical/fallback dependencies or unrelated user edits. Unknown reachability/ownership → quarantine, not delete.

**Permanent GC:** after every assimilation, failed publication and as standalone operation, find orphan modules, missing manifest targets, unbound/duplicate/numbered/scaffold/fidelity-rejected modules, stale tests/index/cache/MCP exposure, retired implementations, knowledge incorrectly made executable and generic fake processors. Atomically remove only proven generated-owned unreferenced artifacts; retain source, knowledge, lifecycle/audit and receipts; emit cleanup receipt; keep compact canonical active views. Second identical cleanup must make **zero changes**. Do not count the absence of garbage as proof of real capability use.

## Conjunctive behavioral acceptance (two historical A–L suites)

1. **Mixed-source classification:** executable code vs README/AGENTS/changelog/config/data/junk; only real behaviors routable, with stable provenance and schema.
2. **Contract completeness and migration:** every active native/adopted/assimilated contract has intents, typed schemas, effects/safety, provenance, target, fidelity and verifier; persisted legacy records still load.
3. **Fidelity:** fake echo/`processed=True` rejected, faithful fixture reaches verified routing.
4. **Retrieval and provider outage:** correct natural-language top-K among distractors; deterministic safe fallback when semantic provider unavailable.
5. **Negative routing:** unrelated request → `NO_MATCH`, no irrelevant tool execution.
6. **Invisible automatic use:** after assimilating uniquely identifiable tiny fixture, plain request without source/module name routes and executes correct capability.
7. **MCP scaling:** +100 fixture capabilities do not inflate normal tool list by +100; target remains discoverable.
8. **Competition/fallback:** preferred compatible candidate fails postcondition; safe second candidate succeeds, with telemetry and bounded retries.
9. **Composition:** two compatible fixture abilities, typed acyclic output→input binding, final verified result; cycles and invalid mapping fail.
10. **Same-process hot use:** new fixture available immediately after successful publication, no restart/reconnect.
11. **Atomic rollback:** inject failure after partial publication; no half-live contract/index/manifest/cache/runtime entry, original source and audit retained.
12. **Cleanup/idempotence:** polluted historical fixtures non-routable; no orphan/stale/duplicate/scaffold/fidelity-rejected generated artifacts; two consecutive cleanup runs, second zero changes; re-assimilation of identical/equivalent sources does not clone.

The first general prompt additionally separates repeat-assimilation and equivalent second-source tests and requires scale under bounded context; the baseline-specific prompt emphasizes admission/contract schema and NO_MATCH. **Both** require all A–L plus relevant regression tests and honest inventory inspection. Do not substitute a new test file or claimed PASS for executed Ground.
