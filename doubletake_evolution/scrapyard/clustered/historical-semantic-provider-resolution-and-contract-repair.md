# CL-SEMANTIC-PROVIDER-001 — Historical governed provider resolution and contract repair

**Scope / trust:** Distillation of three dated, public scrapyard Agent_X repair specifications. Historical source assertions are **not** current private DT facts, implementation approval, executed tests or Ground. No private source or incident log is reproduced. Preserve the distinction between transport availability, schema compliance and mutation authority. Historical source blobs are recoverable in Git history.

## Distinct mechanisms and incident evidence

**SPR-01 — Provider/bootstrap availability** (historical audited Agent_X main `5ebf471c09a6c18585c2b67f1b16ecf2ceaa06f0`). Source alleges write-capable UI requests failed before coding runtime with `SEMANTIC_PROVIDER_UNAVAILABLE`, despite existing provider abstraction; a raw discovery call ignored configured model/base URL/token and cache. The historical source proposes using the *existing* env-aware factory, configured-model-first selection, capability/entitlement-aware live-or-cached discovery, bounded candidate failover and short-lived last-known-good **only after a successful bounded completion/probe**. No hard-coded permanent model or entitlement inference. Existing semantic reasoning stays tool-less/read-only; the real coding runtime may receive write authority only after a valid governed transaction. Avoid new competing provider resolvers, an extra health call per ordinary request, unbounded retries, secret persistence or credential logging.

**SPR-02 — Schema/authority contract repair** (historical audited Agent_X main `b79273a7ffcac5616b40f151cc322fa8499a5210`). Source alleges interpretation succeeded but target-design responses from multiple models failed `CONTRACT_MISMATCH`, because valid JSON containing invalid `authority_decision` enums was not eligible for the JSON-repair path. Keep exact machine authority values `deterministic`, `prompt_driven`, `prompt_only`; human display labels, case variants, hyphens, spaces, `automatic`, `llm` and unknown values are **not** direct authorization. Extend **one** same-model governed bounded repair to `INVALID_SEMANTIC_JSON` and `CONTRACT_MISMATCH` before candidate failover. Supply sanitized field/index/value/allowed-values validation detail, original response and narrow repair instruction; revalidate with the unchanged strict validator. A repaired answer may change only invalid/missing schema fields, not already-valid architecture. Detect drift on unchanged fields (especially authority), fail closed if semantic intent cannot be preserved. Never silently coerce enums in application code or accept structural fallback as authority.

**Shared lifecycle / reconciliation:** UI reserves run identity → semantic provider resolution → governed prompt/repair → strict interpretation and target design → exact semantic authority and write/effect scope → authorized coding runtime → actual verification → canonical reconciliation and independent second no-change `SYNCED` check. This is a *required historical test design*, not a proven current execution. A failed pre-authorization request must not leave a durable authoritative transaction or stale reusable grant; background/other runtimes must not bypass the same gate.


**SPR-03 — Repeated semantic completion timeouts and bounded failover** (historical audited Agent_X main `6d62cc4eada5c29a75a638291fe7e39af56c1693`; reported 503 `SEMANTIC_PROVIDER_TIMEOUT` on an ordinary build request, followed by the same failure on retry). This is a separate *transport and selection* failure, not proof that a provider was healthy or that the current DT has the same bug. Historical source points to `tools/agentx_evolve/providers/api_provider.py` accepting `**kwargs` without forwarding bounded output controls, `resolve_ui_semantic_provider(timeout_seconds=120)` copying 120-second timeouts to as many as four candidates, ranking by largest context window, and uninformative API errors. Those are historical source claims requiring present-day source verification.

- **Transport diagnosis before code:** From the same authorized runtime, check models endpoint, a tiny tool-less JSON completion (`max_tokens: 32`), and a representative schema-sized bounded JSON completion; record sanitized status, latency, selected candidate and response size. Mock deterministic negative tests must work even during provider outage.
- **Bounded generation:** Allowlist and validate only supported `max_tokens`, `temperature`, `top_p`, `stop`, and *only if verified* `response_format`; reject/ignore arbitrary kwargs rather than forward them. Ordinary chat without kwargs stays compatible. Interpretation, target design and JSON repair need **separate measured output budgets** (historical 1,500–3,000 tokens is an illustrative range, not a current recommendation). Use deterministic temperature only where supported; if optional parameter unsupported, classify compatibility error and preserve the output bound.
- **One stage-wide deadline:** Use monotonic remaining time, bounded per-candidate attempts and `sum(attempt waits) <= stage deadline`; do not give each of four candidates a fresh 120 seconds. Separate connection/read timeout where practical without wholesale transport rewrite. Skip attempts with insufficient remaining time.
- **Selection/health:** Establish conservative input+output+safety context sufficiency, but do not reward context size beyond sufficiency; unknown context can be probed without automatic preference. Prefer configured eligible model, recent successful semantic completions, JSON capability, current availability and measured latency; use bounded non-secret recent health and expiring cooldown. A timed-out last-known-good is demoted, not permanently blacklisted. Successful failover updates last-known-good. No hard-coded model-name replacement, entitlement inference or authentication changes.
- **Truthful diagnostics:** Stage (`interpretation`, `target_design`, `json_repair`, conflict resolution if relevant), model/source, attempt, elapsed time, failure bucket and failover go to capped sanitized API/run-local evidence (`semantic_provider_failure.json`), never credentials, prompts, response bodies or Authorization headers. A successful alternative returns success, not 503; all eligible failures return one bounded truthful 503.
- **Deferred streaming:** Only after real evidence that bounded non-streaming fails despite quick first tokens, consider tool-less semantic streaming with bounded bytes/deadline and strict final JSON validation; partial JSON is never authorization. Raising 120→300 seconds alone is not a repair.
- **Negative and parity tests:** Mock kwargs compatibility; each stage's output limit; fake-clock deadline with A timeout→B success and all-timeout→skip C; context/health ranking; cooldown expiry and retry; anonymous vs token eligibility; stage-level sanitized diagnostics; no structural fallback, malformed-JSON or timeout grant, no stale transaction, exactly one target after successful failover; normal UI→semantic target→authorized coding runtime and independent double `SYNCED` check only after permitted canonical reconciliation. No host tests or present-DT implementation were observed in this Scout review.

**SPR-03 unknowns:** current DT resolver and transport parity; actual external service health; original tests/host receipts; source/license rights and authorized runtime access. Revisit only on a current independently reproduced provider-selection/timeout regression. Do **not** claim this resolves B1 protected history, B7 mission-consumer receipt, natural cycles or external assimilation.

## Error taxonomy and negative evidence

- **Provider/transport:** discovery/network failure, timeout, unavailable model, rate limit, authentication failure, server error. Prefer existing typed error buckets; candidate failover only for genuinely retryable failures. A shared invalid credential or deterministic malformed request should not cause a pointless model storm. Cached last-known-good is time-limited and verified, not permanent truth.
- **Response-shape:** empty/malformed provider envelope. **Semantic JSON:** fenced/wrapped recoverable JSON may be extracted unambiguously; ambiguous/malformed content gets at most one governed repair and strict validation, not guessed architectural fields. **Contract:** valid JSON but wrong field/enum/type/missing requirement is not a network timeout and must not poison timeout-health cooldown.
- **API truthfulness:** policy denial remains 403; temporary provider outage is service-unavailable/retryable; malformed or invalid semantic output is a distinct gateway/contract failure. Browser diagnostics sanitize provider content and expose bounded attempt stages, not raw prompts or tokens. Structural evidence may accompany an error but cannot silently turn into permission.
- **Canonical schema:** human labels and serialized tokens are different; avoid pipe-delimited pseudo-enums in JSON examples. Decide explicitly whether `component_type` is closed and whether top-level `verification_strategy` is mandatory/consumed; prompt, validator, repair instruction and tests must share one source of schema truth rather than drift.
