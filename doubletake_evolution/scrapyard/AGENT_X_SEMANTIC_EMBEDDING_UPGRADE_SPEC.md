## Core contract and authority
Semantic inference is **evidence only**. Existing deterministic policy, human approvals, allow/deny rules, tool-effect enforcement, source identity, hashes, sandbox, Shepherd/liveness and governance retain final authority. Never allow embeddings, inferred predicates, memory similarity, relation arithmetic or provider fallback to authorize an effect, promote a patch, overwrite memory, waive tests or override a hard rule. Exact SHA/content hashes remain authoritative for identity, integrity, exact duplicates and provenance; vectors serve approximate relevance only. High cosine similarity proves neither truth nor entailment, equivalence, contradiction, causality or permission.

Authorize and safely read source **before** prompt-injection filtering, redaction, remote embedding, semantic ranking/deduplication/contradiction and ordinary context packing. Blocked sources must never be embedded. Remote provider requests, logs and evidence must not leak unredacted secrets.

## Strict semantic-space identity and numerical gates
Derive `space_id = SHA256(canonical_json(profile))` from provider, model, revision/endpoint, dimensions, normalization, input role/instruction/prefix, chunking, pooling and geometry version. Reject cross-space similarity, index search, subtraction, arithmetic and predicate construction. Strict wrapper over the existing provider must check availability, expected provider/model, dimensions, finite values, nonzero norm, nonempty identity, and normalized vector when required. Reject NaN/Inf, zero/fallback vectors, padding/truncation, missing calibration and mismatched semantic space with typed errors; no invented evidence. Ordinary retrieval may fall back to deterministic lexical ranking when provider fails; semantic algebra must fail closed.

Historical API candidates: `SemanticSpaceProfile`, `SemanticEmbedding` (space/model/provider/dimensions/vector and text/vector hashes), `SemanticMatch` (object/score/evidence), `SemanticEvidenceRecord` (operation, EVIDENCE_ONLY authority, space, refs, calibration, hashes, warnings/errors), `SemanticConflict` (pair, scores, scope, status, calibration, evidence), `RelationModel` (type, vector hash, training refs/count, held-out metrics, status), `StrictSemanticEmbeddingProvider.embed/embed_batch`, `SemanticService`. Avoid serializing raw vectors into routine audit JSON; use a referenced durable BLOB.

## Historical correctness fixes and retrieval design
Historical Agent_X `context/deduplication_engine.py` bug: sort lambda incorrectly referred to `_ctx['i'].priority_score`; correct expression is `lambda i: i.priority_score`. Regression: >=3 items with differing scores and one exact duplicate; no exception, correct dedupe count, descending priority. **Not verified in DT.**

Historical repository context was path-only; use authorized real file content, bounded safe reads, text/load status, source hash, language, byte/line ranges and explicit unavailable/error evidence. Chunk by structure (Python AST, TS/JS, Markdown heading, fallback windows), preserve origin, offset, hash and chunking profile; never silently treat path strings as content. Context items may carry `semantic_relevance_score`, `semantic_space_id`, `semantic_evidence_ref` without modifying trust classification. Perform semantic work after filtering/redaction and before packing/compression. Hybrid ranking example: trust .35 + semantic .35 + lexical .10 + constraint .10 + target-file .10; these are *illustrative*, not validated thresholds. Clamp [0,1], preserve exact target-file recall and deterministic fallback.

Keep exact dedup separate from semantic paraphrase suggestions. Semantic matches require calibration and metadata/scope checks; contradictions take precedence over dedup. Never silently merge distinct constraints or policies.

## Durable index, relations and provenance
Proposed SQLite tables:
- `semantic_vectors`: record/object IDs and kind, scope/status, space_id, text/vector SHA256, dimensions, f32le BLOB, source_ref, timestamp, metadata; index by space/kind/scope/status/text hash.
- `semantic_edges`: edge ID/type, source/target IDs, space_id, primary/secondary score, calibration_id, status, evidence_ref, timestamp, metadata. Types: SEMANTICALLY_SIMILAR, POSSIBLE_PARAPHRASE, POSSIBLY_CONTRADICTS, SUPPORTS, TRANSFORMS_TO, REPAIRS, REGRESSES_FROM, RELATED_TO.
- `relation_models`: relation ID/type, space, vector SHA/dimensions/BLOB, training count/refs, metrics, status, timestamp.
API candidates: `upsert_embedding/get_embedding/delete_object/search/add_edge/list_edges/save_relation_model/get_relation_model`. Search filters scope/kind/status **before** cosine, only same-space vectors; brute-force cosine acceptable for small historical scale. Bind records to immutable source identity, revision, provenance and versioned calibration; invalidation/reindex on source or geometry changes. Keep evidence append-only/traceable and distinguish predictions from validated facts.

## Contradiction and compression
Retrieve nearby claims, then evaluate pair features `|u-v|`, elementwise `u*v`, cosine with a separately calibrated contradiction classifier or governed NLI model. **Never** infer contradiction as `1-cosine`. Use calibrated low/review bands; possible conflicts go to review, not automatic policy resolution. Resolve explicit scope/time/version differences deterministically when available; otherwise retain uncertainty. Suggested conflict states: POSSIBLE, SUPPORTED, RESOLVED_A_WINS, RESOLVED_B_WINS, BOTH_CONTEXTUALLY_VALID, SUPERSEDED, INSUFFICIENT_EVIDENCE, FORMAL_CONTRADICTION, FALSE_POSITIVE. Preserve competing claims and evidence in context compression; never compress a disagreement into false consensus.

## Durable memory, regression and experimental relation geometry
Attach semantic evidence to memory candidates **before** existing deterministic learning-policy decisions; keep existing learning index/policy as owner. Classify exact duplicate, paraphrase, related-but-distinct and possible contradiction separately. No automatic overwrite/promotion. Link current failures to verified historical regressions/repairs as retrieval evidence, not proof.

Experimental relation types: FAILURE_TO_REPAIR, PROPOSAL_TO_PROMOTED, REJECTED_TO_CORRECTED, DRIFTED_TO_CANONICAL, UNSUPPORTED_TO_VERIFIED. For verified same-space pairs `(F_i,R_i)`, compute mean `r = mean(E(R_i)-E(F_i))`; retrieve candidate repairs using `E(new_failure)+r`, but never decode vector into code or execute a repair automatically. Compare held-out top1/top5/MRR to ordinary nearest historical failure baseline; enforce train/test incident separation, minimum pair count, deterministic repeatability, variance/alignment checks and measurable improvement before VALIDATED status.

Optional calibrated predicates (EXTERNAL_EFFECT, SENSITIVE_DATA, IRREVERSIBLE_EFFECT, PRIVILEGE_CHANGE, SECURITY_RELEVANT, REQUIRES_HUMAN_REVIEW) can compose Boolean warnings after thresholding; they may **tighten** deterministic review but never relax policy. Preserve predicate probability, threshold, space/calibration/evidence refs. Do not insert inference inside deterministic `PolicyEnforcer.enforce()`.

## Falsifiable tests and rollout gates
1. Provider/space: reject missing/mismatched model/provider, wrong dimensions, NaN/Inf, zero vector, cross-space algebra, missing calibration; ensure safe fallback for retrieval only.
2. Source loader: path-only, unreadable, blocked, injection-bearing, oversized, binary, out-of-workspace and secret-containing files do not leak or masquerade as trusted text; chunk provenance survives.
3. Context: compare lexical/path baseline vs hybrid on Recall@5/10, MRR, precision@K, target-file retention, tokens and gold coverage/1k tokens. No material loss of exact targets; improvement must be measured, not assumed.
4. Dedupe: labeled EXACT_DUPLICATE/PARAPHRASE/RELATED_BUT_DISTINCT/CONTRADICTORY/UNRELATED pairs; measure precision, recall and especially **false merge rate**; no distinct policy/constraint collapse.
5. Contradiction: scope-aware policy/plan/memory/evaluation pairs; measure precision/recall, PR-AUC, calibration error, false negatives and review-budget tradeoff; split by semantic family and time.
6. Learning: contradiction/review evidence cannot bypass human approval or deterministic memory policy; replay and audit evidence stable.
7. Relation: held-out failure→repair top1/top5/MRR and no leakage; must beat similarity-only baseline before use.
8. Security: no blocked or unredacted remote embeddings, no model identity laundering, no false PASS on missing provider/benchmark, no unauthorized effects.

Roll out in stages: correctness/provider/space identity → shadow retrieval → measured hybrid ranking → semantic dedupe suggestions → contradiction-aware memory → contradiction-preserving context → regression linkage → experimental relation vectors → optional predicates. Keep each stage off until its own evidence and negative tests pass. Immutable/versioned calibration profiles bind threshold decisions; historical example weights and thresholds are **not** production defaults. Defer vector DB migration, automatic patch execution, autonomous memory promotion and semantic authorization. No current DT runtime or code parity has been established.
