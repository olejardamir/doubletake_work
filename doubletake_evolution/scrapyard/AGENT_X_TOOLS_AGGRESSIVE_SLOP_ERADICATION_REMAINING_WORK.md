For every helper, module, shim, registry, test and persisted record: trace **real** production/API/CLI/plugin/dynamic/config caller → behavior needed → canonical owner → alternative implementation → provenance and authority → affected positive/negative tests. A test importing a helper or a snapshot pinning an old API is not itself a production need; neither is absence from static imports proof of deadness if dynamic loading/external contracts exist. Remove truly dead/duplicate code only after migrating active readers, checking current SHA, preserving unique behavior and acknowledged state, and verifying regression/rollback. Prefer deleting dead code over adding another facade, manager, registry or compatibility wrapper. Preserve working algorithms, real orchestrators, governance, persistence, behavioral gates and legitimate API contracts.

## Falsifiable checks

1. Duplicate evidence → `ALREADY_EXISTS` with no new Python/test/manifest; vague evidence → `CONCEPT_ONLY` or `DEFERRED` with no executable artifact. No stale manifest/status may reactivate retired code.
2. Independently needed real capability → actual author→substantive mechanism→behavioral test→evidence/substance gate→targeted execution→canonical owner→atomic promotion/rollback→real runtime registration/caller. Metadata-only and import-only tests do not count.
3. Authority, integrity and concurrency: missing grant, forged source, stale revision, crash/restart, concurrent promotion, retry, rollback failure and old state must not cause unauthorized effects, duplicate landing, lost accepted writes or false `IMPLEMENTED`.
4. Execute affected `algorithmic_substance_gate`, `test_write_code_e2e.py`, full `test_coding_loop.py`, assimilation governance, promotion, harvested algorithm, manifest/runtime and Borg integration tests; record exact commands and results. **This Scout did not run them.**
