## Shared historical principles (one copy, not repeated 30 times)

1. **Canonical-owner before integration.** Map live callers and source authority before treating donor names or generated code as canonical. One Gate B, embedding/index, scheduler, persistence, promotion and UI authority; migrate distinct mechanisms into existing owners before deleting redundant donors. Historical source baseline: `Astrocytech/Agent_X` at `874bbe4268aca0539cbf8476f62444d704f2d555`; **not** evidence of the current DT HEAD.
2. **Governed knowledge is not executable authority.** Source-grounded semantic proposals precede code; server-side approval is revalidated at execution; UI, model confidence, generator fitness, donor registry, embeddings and mere status labels cannot grant implementation rights. Unknown scope, provenance, hard invariants and stale decisions fail closed.
3. **Evidence→effect→independent Ground.** Preserve real caller paths, immutable evidence/provenance, held-out comparisons, negative controls, restart/idempotency, rollback and release state. R0–R6 and strict end-to-end checks are historical *requirements*, not completed measurements. A high proxy score, a passing donor-only unit test, or a green digest of a lossy snapshot is insufficient.
4. **Provider extension without authentication fiction.** The historical LLM7 plan describes optional anonymous OpenAI-compatible chat, dynamic models and model/access-specific tools. Its 2026-09-11 no-auth example is **not a present-day service entitlement**. No synthetic API key, credential prompt or Authorization header should be added solely to satisfy an SDK. Recheck live protocol and current provider code before any work.
5. **No-loss contract precedes consistency checker choice.** External Porcupine/Elle literature can provide a separate operation-history oracle, but the existing DT source/tests already characterize a lost acknowledged write in isolated fixtures. The missing owner-approved contract and independent authorized runtime are more important than adding a checker. A stronger linearizability assumption must not be smuggled into a weaker accepted-set durability contract.

## D01 falsifiable candidate and Director-facing knowledge gap

Controls: accepted `a` then `b` with final `{a,b}` PASS; both accepted but final `{b}` FAIL; `a` refused before ack with final `{b}` PASS; missing acknowledgement INCONCLUSIVE.
