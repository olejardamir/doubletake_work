## Historically alleged defects and minimal mechanisms

1. **Fake accepted-baseline evidence.** Historical baseline used labels `accepted_target_digest="structural-correction"` and `verification_digest="deterministic-verification"`. A self-consistent outer JSON digest does not authenticate underlying artifacts. The sealed target digest must recompute from the exact accepted change/run/repository, source and base revisions, request, architecture decision, write/effect scope and verification obligations. The verification digest must recompute from issued evidence bound to the same change/target/run and resulting implementation revision, effects, checks, issuance and one-time consumption. Reconciliation revision must be produced canonically, not caller-supplied. Reject labels, arbitrary 64-hex strings, missing/deleted evidence, cross-run/change references, stale/replayed/consumed evidence and copied target/verification fields without schema-defined equivalence.

2. **Production snapshot polluted by nonproduction files.** Historical `implementation_revision` reportedly included tests (`tools/agentx_evolve/tests/test_*.py`, benchmark tests), wishlist, human reports and archives. Classify by **deterministic actual production consumption**, not extension, Git tracking or filename: production code/frontend/runtime prompt/config/schema/required data versus tests/evidence/generated state/human docs/research/wishlist/archive/secret/unknown. Test edits may change a separate evidence revision but not production implementation. Runtime-consumed Markdown/config must count; unrelated JSON/YAML/TOML must not. Unknown authority blocks false `SYNCED` when material. Untracked production source must be visible before commit. Preserve role classifier itself as protected production implementation.

3. **Test-only capabilities in accepted semantic model.** Historical model included `benchmarks.benchcore.tests` as a production capability. Regenerate a *candidate* from corrected deterministic discovery plus governed semantic enrichment, validate against actual runtime owners, then accept. Tests are `verified_by` evidence, not automatically capability owners or production invariants. Reject pure test-suite/CI/wishlist capabilities, duplicate or orphan responsibilities, conflicting owners, stale identities and arbitrary assertions promoted to architecture; preserve stable IDs for unchanged real production responsibilities. Do not manually delete individual accepted JSON objects.

4. **Nonportable canonical identity.** Historical baseline tied canonical acceptance to a particular absolute checkout path (omitted here). Separate portable committed repository identity, semantic/implementation revisions and artifact-backed bindings from local transaction identity (absolute workspace root, worktree/workspace ID, epoch, run). Fresh checkout B at another path of the *same tree* must independently report `SYNCED` without rewriting canonical state; a mutation grant issued in checkout A must **fail** in B.

5. **Browser-disconnect background completion bypass.** Historical OpenCode disconnect path could reconcile provider telemetry and set durable `completed` without canonical semantic finalization. Foreground and background must share one finalizer: provider ends → durable `provider_completed/verifying` → exact effects and tests → semantic enrichment/reconciliation → accepted baseline promotion → only then completed. On verification error/timeout/conflict, fail or conflict, revoke mutation authority and preserve recovery/rollback evidence. Negative boundaries: disconnect before effects, after partial effects, after provider finish but before finalization, exception, timeout and restart during finalization. Provider success alone is not task completion.

6. **Wildcard fallback for opaque LLM7/MCP tool effects.** Historical argument extraction could fail to find a file path then authorize via a wildcard transaction check. Instead require registry-backed typed effect contracts: read-only; exact file; bounded multi-file; Git; DB/durable state; dependency/environment; service/runtime configuration; remote durable; unknown. Bind validated arguments to exact resources, semantic target and ordinary tool/MCP policy. Unknown/unregistered/malformed/unextractable effect **DENY** unless an already-authorized target amendment is sealed. A falsely declared read-only tool observed mutating must fail/quarantine. Negative matrix includes unusual argument keys, out-of-scope file, multi-file, Git reset/checkout/commit, DB, install, service, remote write and real read-only query.

7. **Legacy transaction pile and terminal state leakage.** Historical `semantic_project/changes/<change_id>.json` persisted after run-local overlays replaced it; some terminal transactions remained `active`. Any migration must inspect each record's schema/digest and references from active run, conflict, recovery or accepted evidence. Migrate still-authoritative records to the correct run/conflict store; only compact/delete terminal unreferenced material **under owner-approved retention/no-loss rules**. Never blindly remove the directory or rewrite protected history. Ensure old backends cannot recreate it; mark completed/no-op/rejected/aborted/superseded/rolled-back/conflicted transactions terminal, with bounded recovery retention and immutable audit pointers. **Present DT B1 historical-integrity disposition remains owner-blocked; this historical proposal is not permission to modify it.**

## Independent acceptance/negative tests (historical design only)

| Fixture | Required observable result |
| --- | --- |
| Baseline with fake/cross-run/stale/replayed/missing target or verification evidence | Reject despite valid outer digest; recompute inner artifacts and compare issued/consumed identity. |
| Change production API/frontend or runtime-loaded prompt/config/schema | Production implementation revision changes. |
| Change test-only code, benchmark tests, wishlist, archive, human document, runtime logs | Production revision **unchanged**; test change may alter evidence revision. |
| Candidate semantic model with test-suite capability or test assertion as owner | Reject/resolve before acceptance; real production IDs remain stable. |
| Same committed tree in different checkout | Canonical state portable and independently `SYNCED`; cross-checkout run authorization denied. |
| Background provider finishes after browser disconnect, before finalization | No durable `completed` until canonical effects→verification→reconciliation→promotion; failure is non-success. |
| Opaque or wrongly declared read-only effectful tool | Denied, no unauthorized side effect; correct exact-resource contract required. |
| Legacy overlays: stale, terminal, unresolved, active/referenced | Preserve live/conflict/recovery/evidence; terminalize and compact only after retention authorization, restart protection. |
| Source/semantic/both diverge or stale backend | Explicit conflict/fail-closed, not synthetic synchronization. |

**Historical remint order:** correct classifiers/effect contracts/overlay lifecycle; take production snapshot and separate verification revision; regenerate and quality-check semantic candidate with governed enrichment; run real production behavior tests; issue exact sealed target and verification evidence; reconcile; build/persist model+baseline transactionally; reload and validate all inner bindings; independently assess `SYNCED`; fresh-checkout `SYNCED`; immediate unchanged second `SYNCED`. No hand-edit of accepted model or status. Ordinary UI mutation must traverse the complete governed lifecycle, while true read-only requests produce no mutation transaction and provider-unavailable write requests grant no authority.

**Negative acceptance rule:** `SYNCED` string, passing compilation, named tests without execution, commit message or historical prompt inclusion are not proof. Historical non-regression claims (run identity before writes, mandatory semantic-first in Borg, exact effect enforcement, fail-closed startup, isolated tests, explicit drift, no provider-prose completion) must be independently checked against current source and runtime. No authorized present-DT assimilation, runtime cycle, owner-history decision or downstream improvement follows from this record.
