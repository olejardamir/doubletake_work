## Source-backed mechanism and important limits

EffectMatch separates (1) an **independently approved outcome** A, fixed before execution by the application/task owner, (2) the **observed persistent effect multiset** E, and (3) a **durable continuation decision** for one authorized execution. At a declared, certified observation boundary and comparison granularity, classify EXACT only when completeness is established and E=A; DIVERGED if complete but different; INDETERMINATE when coverage/attribution is insufficient. Extra, omitted and duplicate changes matter even if the tool call returned success. A backend with staged/promotable writes can refuse commit; an opaque external backend cannot undo realized effects merely by observing them and must withhold dependent work on divergence or uncertainty. This is not equivalent to checking requested output alone.

The authors report 618/618 clean-reference executions retained and zero incorrect commits in selected 206-task reference comparisons; independent-approval experiments were much smaller (three PostgreSQL tasks and twelve business tasks). A GitHub remote-readback study covered **registered issue fields only**; the authors explicitly say its readback did **not** attribute an out-of-band title change to the evaluated request. The tested PostgreSQL outlet-certification matrix is not exhaustive. Author-reported median held/direct runtime ratio was 4.35x in 18 fast local task comparisons, with 1.08 ms median added time; this does not predict DT cost. Results are not independently reproduced, and complete observation must not be inferred from a successful readback or tool receipt.
