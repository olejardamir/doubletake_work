## Distinct reusable mechanism and limits

Application/agent trace = *declared semantic action*; OS trace = *observed process/file/network effect*. Neither alone establishes a causal mission→action→effect chain. Preserve source identity, independent observation, inference method, causal status and unknowns separately. Temporal coincidence is not attribution. A heuristic command→process match is only an **inferred non-causal** link; abstain if zero or multiple compatible observed processes. Even one compatible process can be an impostor if the true process was missed. A file-open event proves neither exact bytes read nor use of those bytes in a decision; session-correlated file events do not identify the responsible agent. Shared identifiers can support identity without proving causality.

**Author-scoped evidence:** ExecWeave v0.8.25 Linux/AutoGen–Ollama example: four model requests/responses, three semantic process references resolved, 60 nodes/61 edges. In a 5-ms-child condition, portable 20-ms polling observed 18/30 vs 0/30 at 500-ms polling. Reported fixed-work overhead: +408.8% micro, +85.2% medium, +62.3% long. These are author-run workloads, not DT results; Linux only, no general provider/OS parity, no guarantee of causal correctness or low cost. Runtime traces can contain prompts, secrets and confidential paths: keep synthetic or separately authorized redacted fixtures private.
