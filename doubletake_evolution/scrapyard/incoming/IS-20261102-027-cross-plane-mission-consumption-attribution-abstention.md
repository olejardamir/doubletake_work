## What the source actually establishes, and what it does not
Agent/tool **semantic traces** report declared actions; independent **runtime observations** report processes/files/sockets. A timestamp match between them is not an authenticated causal connection. ExecWeave keeps source observations separate and labels heuristic command→process links *inferred and non-causal*, abstaining when the observed compatible process set has zero or multiple candidates. **Important counterexample:** if the real process is missed and only one impostor is observed, even singleton matching can make a false link. A successful file-open syscall proves neither the exact bytes read nor that the agent used those bytes in its decision. A session-correlated filesystem event does not identify its actor.

Author-run evidence (not independently reproduced): one AutoGen–Ollama Linux integration with four model requests/responses, three semantic process references resolved and 60 graph nodes/61 edges; short-lived process detection fell from 18/30 at 20-ms polling to 0/30 at 500-ms polling in one 5-ms-requested-child condition. Paired portable-observer overhead was +408.8% (micro), +85.2% (medium), +62.3% (long) on selected workloads. The paper explicitly disclaims cross-platform/provider parity, generalized causal correctness, and low-overhead deployment. Stronger OS observation still does not alone prove *semantic* mission use. This is evidence about observability limitations, **not** a demonstrated DT defect or remedy.
