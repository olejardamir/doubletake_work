## Independently checked source facts and caveats

- Just, Jalali, Inozemtseva, Ernst, Holmes & Fraser, *Are Mutants a Valid Substitute for Real Faults in Software Testing?* (FSE 2014), DOI 10.1145/2635868.2635929, author bibliography: https://homes.cs.washington.edu/~mernst/pubs/mutation-effectiveness-fse2014-abstract.html . Their **357 real faults in five Java projects** show mutation detection correlating with real-fault detection after accounting for code coverage. The original Internet note additionally reports ~230,000 mutants, 17% uncoupled real faults and 10% needing stronger operators; those detailed percentages were **not independently reproduced here**. This is not a DT or Python result.
- Petrovic, Ivankovic, Kurtz, Ammann & Just, *An Industrial Application of Mutation Testing: Lessons, Challenges, and Research Directions* (2018), https://research.google/pubs/an-industrial-application-of-mutation-testing-lessons-challenges-and-research-directions/ . Many mutants are redundant, equivalent or unproductive; maximizing global mutation adequacy is neither necessarily practical nor desirable.

## Distinct hypothesis and bounded falsifier

Mutation sentinels would test whether a *specific existing safety assertion* detects a near-miss implementation, **not** prove patch application, natural mission consumption, B1 integrity disposition, or external assimilation. It differs from IS-015 (filesystem check/use race), IS-017 (agent termination oracle), IS-010 (history linearizability). Existing DT tests may already detect every applicable mutant; parity is **UNKNOWN**.

**Only if an existing owner-approved disposable Python fixture and exact canonical test command are identified:** freeze source/test SHA, property, runtime budget and 4–6 non-equivalent one-change behavioral mutants before seeing outcomes. Candidate properties: stale evidence incorrectly accepted, failed durable acknowledgment treated as success, fail-closed decision bypassed, nonterminal event treated as completed. Run unchanged baseline, each mutant, an intentionally equivalent/irrelevant mutation (do not count as a fault), a known-fault positive control and unrelated passing control. A mutant counts as killed only when a **property-specific assertion** fails, not syntax/import/environment breakage. Compare current tests (A), same-budget improved assertions (B) and line coverage (noncausal comparator).
