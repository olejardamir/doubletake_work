## Mechanism and distinctive value

A perturbation is evidence about the **same task** only if it preserves protected task facts, relations, allowed authority and required outcome, and leaves at least one permitted completion route feasible. A replayed old solution failing after a route changes does **not** prove the task is impossible; a small semantic/embedding distance does **not** prove the task stayed the same. Separate (a) **test-instance validity**, (b) **actual agent behavior**, (c) **independently observed destination state**, and (d) **scoring/verdict**.

The counterexample is not just “test more”: an evaluator may label an agent unsafe because the *trusted target was changed* (no longer the original task), or label it robust because a threshold rejected valid hostile changes. A different failure arises when a tool claims success without a real effect. These errors cannot be repaired by adding a receipt field or scoring a tool-return string.
