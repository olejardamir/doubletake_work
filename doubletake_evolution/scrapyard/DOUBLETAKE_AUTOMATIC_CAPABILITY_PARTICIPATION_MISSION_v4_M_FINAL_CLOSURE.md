## Invariant and observed historical gap

**M / user abstraction:** removing capability names from a user's request must not materially reduce appropriate capability utilization. A user describes a need or outcome; runtime inventory discovery and routing identify suitable capabilities without relying on the model's memory of their names (criterion N). Historical v4 expected A–L and N–T PASS, M OPEN, `test_no_criterion_is_open()` red; this is **not** a current status claim. Historical evidence surfaces: `tools/doubletake_evolve/tests/test_capability_participation_convergence_table.py` and `tools/doubletake_evolve/collective_core/test_capability_nameless_reach.py`.

Residual: genuinely equivalent request/capability declarations may have no useful lexical overlap (illustrative `relay/link`, `drone/worker`, `remembered/memory`, `redundancy/doubled up`). These pairs are **not** production aliases. Distinguish failure stages: candidate not retrieved, misranked, correctly ranked but refused by coincidence gate, admitted but not executed, executed but uncredited, or semantic source unavailable. The semantic signal must reach the *decisive* downstream gate, not merely improve a scorer.

## Historical negative findings (retest before reuse)

- Lowering lexical thresholds admits false coincidences and risks criterion G; general lexical hierarchy expansion, broad affix/morphology and token-coverage widening did not discriminate positive from negative populations.
- Embedding similarity showed checkpoint-dependent incomplete separation; a probe-fitted cosine cutoff is not evidence of generalization.
- A previous joint-reading/cross-encoder gain disappeared after removing capability-name leakage from hypothesis/description/intent fallback. A name echoed through another field is not nameless reach.
- Scanning more declared strings did not resolve the residual. Revisit only if a genuinely new production surface demonstrates discrimination.

## Transferable production mechanism contract

Use runtime-discovered capability declarations and request semantics to obtain **candidate-specific evidence** of whether the need is served, contradicted or uncertain. Possible mechanisms include an authorized semantic relation/entailment provider or justified combined channels; no preferred model is established by this source. Deterministic capability control retains admission, execution, mutation, budget and orchestration authority. Typed, bounded, observable semantic evidence is advisory; it cannot create a second LLM router or silently promote a shadow-only signal. Provider timeout, malformed output, abstention or absence must produce truthful bounded fallback, never fabricated confidence. Provider/model changes must not silently invalidate calibration. Use current provider/inference permissions.

Forbidden: inventory-specific synonyms/IDs or aliases, current-probe-derived thresholds, held-out examples in production prompts, implicit model recall of inventory, capability-name leakage through fallback, test-only helper routes, and status/report-only closure. New capability registration must work without central-router edits. Preserve discovery, selection/composition, reevaluation, dynamic registration, recovery, conflicts, bounded execution, observability, production reachability, usefulness suppression and extensibility; do not regress criterion G or N.

## Falsifiable acceptance populations and tests

1. **Matched positive:** named request and meaning-equivalent name-stripped request route to the same appropriate real-inventory capability, including zero-useful-overlap cases; test actual production dispatch/use, not only ranking. Hold out fresh paraphrases and forbid production access to evaluation labels.
2. **Matched negatives:** unrelated requests and misleading one-word coincidences remain refused. A blanket relevance increase is failure. Confirm multiple genuinely relevant capabilities still compose when applicable.
3. **Extensibility:** register a previously unseen capability; same mechanism works without an ID-specific rule or central edit. Inventory reordering must not alter the decision.
4. **Availability and governance:** provider absent, timeout, malformed, abstain, overclaim, changed model, shadow-only configuration, unauthorized action and exhausted budget are handled safely and observably; no second authority.
5. **Non-vacuity mutations:** remove semantic evidence → positive case fails; force over-admission → negative/G case fails; disconnect production wiring → production-path test fails; replace provider output with a constant → test fails. Verify evidence is *consumed* by the final gate.
6. **Regression:** focused M and G tests, semantic-service failure tests, router tests, A–T convergence table and materially affected capability participation suites execute and pass; old PASS labels alone do not prove nonregression.

Minimal evidence per routed candidate: capability ID, declared surface, contributing channels, available/abstained/contradicted semantic evidence, admission/refusal reason and whether it changed the decision. Preserve actual commands/exits, source revisions, served provider identity, negative controls and independent verifier evidence; do not manufacture PASS.
