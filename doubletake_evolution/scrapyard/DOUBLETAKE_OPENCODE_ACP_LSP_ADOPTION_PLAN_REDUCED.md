## ACP: agent-side wire bridge, not another agent runtime
External ACP client → DoubleTake ACP agent-side bridge → canonical session runtime → governed execution. Historical proposed surface: `initialize`, `newSession`, `loadSession`, `resumeSession`, `forkSession`, `setSessionMode`, `setSessionModel`, `prompt`, `cancel`, `shutdown`; newline-delimited JSON stdio, historical `protocolVersion: 1`. **Recheck the authoritative ACP specification before implementation** rather than treating old version/method names as current facts. CLI serving entry point should follow current conventions.

Map wire sessions and `knownParts` onto the existing durable append-only session/event state and digest identity; no second session database. Resume, load, fork, mode/model changes use the canonical session authority. Capability advertisements reflect only authorized `AllowedUse`/current capability policy; unauthorized capabilities are neither advertised nor executable. Govern at least session open, prompt and cancel effects (historical operation intents `acp.session_open`, `acp.prompt`, `acp.cancel`). Prompt input/context traverses existing source classification and prompt-governance path. Cancel must target the exact active run/session and must not terminate a successor. Unknown, stale, malformed, tampered or unauthorized frames fail closed, sanitize errors and leave no partial unauthorized side effects.

**ACP positive tests:** protocol negotiation/NDJSON round-trip; initialize; new/load/resume/fork; mode/model update; prompt reaches real governed execution; exact-run cancel; shutdown; session-runtime and append-only ledger parity; authorized capability advertisement; correct operation/identity/evidence recording. **ACP negative tests:** malformed/unknown/tampered frames; stale identity or cancellation; unauthorized tool advertisement and invocation; prompt-context bypass; untracked side effects; secret leakage. Deterministic injected fakes may replace external endpoints but not enforcement authority. End-to-end proof should use an external ACP client and verify wire→session→governed effect→cancel→shutdown.

## LSP: governed observational client, not an authority
Historical target: Python first, then JavaScript/TypeScript through one architecture. Implement only necessary LSP initialize/initialized/shutdown/exit, request/response/notification, text-document/workspace, diagnostics, symbols, definitions and references. Typed positions, ranges, documents, workspaces, diagnostics, locations and symbols should preserve protocol meaning. **Recheck current LSP version and language-server support before relying on historical examples.**

Launch only approved language-server binaries (historical examples: pyright, pylsp, typescript-language-server) through the canonical governed process boundary; never accept arbitrary model-supplied executable paths or ungoverned subprocesses. Historical operation intents: `lsp.launch`, `lsp.initialize`, `lsp.request`, `lsp.shutdown`. Bind every launch and request to an authorized workspace/project/session. Reject traversal, outside-root paths, forbidden symlink escapes, mismatched roots and identities. Consume diagnostics, symbols, definitions and references through existing versioned event/evidence and semantic/indexing consumers, **not** a competing project index. Record workspace/file/language, server/version, request, run/session, sequence/time, live/degraded status and source revision where applicable. Observations may inform analysis, context and validation but cannot authorize writes, promotion, capability grants or process launches.

Missing/unapproved server → explicit unavailable/degraded state, never fabricated diagnostics or false successful initialization; existing AST/static analysis remains functional. **LSP positive tests:** protocol framing/typed round-trips; approved Python and JS/TS server resolution; governed launch; workspace-bound requests; diagnostic/symbol ingestion; definition/reference lookup; existing index/event integration; shutdown; AST fallback. **LSP negative tests:** unapproved binary, traversal/symlink escape, cross-workspace access, direct process bypass, missing binary, malformed server output, secret leakage, unauthorized mutation/promotion based on diagnostics. Hermetic protocol/governance tests must run without installed binaries; integration tests use a real approved server when available, otherwise explicitly report that coverage as not run.
