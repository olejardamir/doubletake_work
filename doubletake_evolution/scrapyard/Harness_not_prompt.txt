# Context-aware model routing in the agent harness — validated source note

**Original:** single-URL pointer `Harness_not_prompt.txt`, Git blob `51c5fb30f22bf8c0b2f615a05ceb862532c40d63` (74 bytes). **Primary source:** Sydney Runkle and Eugene Yurtsev, “How to Build a Model Router in the Harness,” LangChain engineering blog, 2026-10-01: https://www.langchain.com/blog/how-to-build-a-model-router-in-the-harness . Original URL preserved; the article was independently read, but its experimental results were **not independently reproduced**. This is a vendor-reported case study, not current DT code or an instruction.

**Mechanism:** Inspect task/trace distribution, pick cost-quality model tiers, classify the first user request using task/domain context already available inside the agent harness, route to the least expensive likely adequate model, and evaluate actual task outcomes rather than just token cost. A generic gateway lacks much of this context. Routing is fixed per thread in the reported implementation; subagents and mid-thread changes were not covered. Re-routing may lose prompt-cache savings.

**Original measured evidence:** 973 A/B-tested Open SWE threads against always using the strongest tier; merged PRs 29.2% routed vs 27.3% control (p=0.49), PR opening 38.9% vs 39.6% (p=0.82), **no statistically demonstrated quality improvement or decline**. Median per-thread cost $0.94 routed vs $2.61 control (**64% lower**); mean −42%, p90 −37%. Routed tier mix: balanced 56%, fast 34%, strongest 10%. Authors stopped a fast-only comparison early due to qualitative complaints, so it has no conclusive metric. A one-week historical thread sample was heuristically labeled; merge rate is an imperfect quality proxy and user feedback sparse. The specific tiers and prices are time-sensitive, not general DT recommendations.

**Conditional DT transfer test:** If an existing authorized DT model-selection seam and versioned real-task outcome oracle are found, compare fixed-best, fixed-fast and task-conditioned routing on frozen representative tasks with matched tool/permission/context, source-pinned model availability and total costs. Require no regressions in independently scored task correctness, safety or unauthorized actions; report median/mean/p90 cost, latency, escalation and hard-task failures. Include wrong initial classification, mid-thread task change, missing provider and prompt-cache invalidation negatives. **UNKNOWN:** current DT routing parity, permitted models, quality oracle, costs and production owner. Do not add a parallel router or new mission without demonstrated delta. Distinct from IS-021: this selects a model tier at thread start; IS-021 decides whether optional rollouts help within an environment. Neither addresses B1 owner authorization or proves DT Ground.
