## 1. Problem and proposed mechanism

**Criterion M:** a genuine capability need expressed without the internal capability name should reach the appropriate real, routable capability. Historical test `tools/doubletake_evolve/collective_core/test_capability_nameless_reach.py::test_m_is_not_satisfied` and `tools/doubletake_evolve/tests/test_capability_participation_convergence_table.py` reportedly kept M **OPEN**. Historical examples: “remembered” versus stored memory, “workers” versus subordinate agents, “link” versus outbound relay, “doubled up” versus redundancy and “single point” versus single failure point. They are *diagnostic examples*, never allowed as hardcoded synonyms, prompts, expected answers or production aliases. Actual current M state and reachability require a fresh private DT check.

**v5 design hypothesis:** run the ordinary deterministic capability path first. Only if genuine semantic evidence is insufficient, use **the already-active OpenCode-connected LLM** for one bounded, isolated semantic restatement of the user's *current* request. Strictly validate the output as immutable interpretive evidence, then rerun deterministic DT routing. The model must not select capability IDs, choose candidates, rank/tie-break, grant permission, order execution, manage conflicts/retries, register/publish capabilities or make final admissibility decisions. No model call inside routine `rank_candidates()`/router control. The final route must be deterministic for a fixed (original request, validated semantic evidence, capability inventory).

**Interpretation example (not a rule):** “is the link out doubled up or a single point?” → “determine whether the outbound connection has redundancy or a single point of failure.” A separate deterministic owner maps the meaning to any available capability. Prefer **inventory-free** interpretation with no capability IDs/names, labels, target answers or conversation history. Only if independently measured necessary, compare an A/B design exposing published **descriptive surfaces without IDs/names**, still forbidding LLM selection. Preserve user operation type, negation, entities, quantities, time, status-versus-action and scope; reject schema-valid but semantically drifted/expanded requests. Do not fit scalar thresholds to M probes.

**Schema boundary:** a small, versioned, bounded, strictly validated output such as `{schema_version, literal_intent, paraphrases[], uncertain}`; no tools, commands, executable instructions, arbitrary nesting or chain-of-thought. On uncertainty, malformed response, timeout, unavailable OpenCode or intent drift: explicit, bounded fail-closed deterministic fallback; **no synthetic success**.

## 3. Acceptance and falsification — preserve G and N

**G is a hard co-gate:** improved nameless M recall must **not** admit irrelevant/coincidental capabilities merely because a request contains words such as “execution” or “continuous”. Preserve coincidence, conflict, safety, permission, routability, duplicate and validation guards. A candidate retrieved but later rejected/excluded/executed incorrectly is not material participation. **N is a hard co-gate:** unrelated prior conversation must not alter semantic inputs or authority; OpenCode unavailable must not trigger model acquisition or unsafe activation.

**Two proof layers, never conflated:** (A) fake-provider/unit tests may prove wiring, schema rejection, no-tools isolation, provider authority, deterministic routing, G/N, timeouts and fallback; (B) **real active OpenCode LLM** proof must show model identity, actual call, returned interpretation, real routable inventory, actual deterministic route/participation, independent nameless/fresh controls and G negatives. A skipped live proof is **NOT PASS**. No synthetic provider can prove real semantic understanding.

**Frozen populations:** existing held-out nameless, fresh independent nameless, name-present counterparts, unrelated/negative and G coincidence controls. No answer-label leakage, probe-derived aliases, threshold fitting, or rewriting failed prompts. Independently repair invalid labels with recorded rationale only. Require real downstream behavior and independent observation, not merely a status or documentation edit.

**Non-vacuity/negative controls:**
1. Disable semantic interpretation: M gains should disappear while G remains safe.
2. Malformed output: reject and fall back without capability activation.
3. Valid JSON but unrelated/intent-changing paraphrase: reject or refuse at the deterministic owner.
4. Inject prohibited model-acquisition call: structural guard must fail; it must not ban legitimate OpenCode transport.
5. Reintroduce provider ranking/authority in routine routing: provider-independence guard must fail.
6. OpenCode unavailable: no alternate model, no download, no fake PASS, explicit bounded fallback.
7. Repeated/concurrent round and changed inventory: no duplicate semantic call, infinite reevaluation, stale evidence or cross-user leak.
8. Real negative/held-out/ablation and unrelated capabilities: no G/N regressions, no uncollected tests, no hidden test exclusions.

**Historical 14 closure gates (condensed):** (1) non-vacuous no auxiliary acquisition, (2) only active OpenCode learned path, (3) cognition/control separation, (4) nameless M, (5) G negatives, (6) N isolation, (7) real inventory, (8) actual OpenCode live proof, (9) honest failure, (10) no probe fitting, (11) mutation/non-vacuity, (12) tests actually collected, (13) truthful M PASS and `test_no_criterion_is_open()`, (14) focused plus authoritative broader/default test result with unrelated failures disclosed.
