1. 2. Distill each noisy source into **zero or more independent candidates**: decompose unrelated ideas; demote fictional/promotional claims, accidental joins, fabricated symbols and unsupported numerical targets without discarding useful source-grounded mechanisms. Normalize problem, mechanism, inputs/outputs, dependencies, constraints, measurable expected delta, evidence and uncertainty. Preserve discarded-claim reasons and source trace.
3. Classify by operational type: `ALGORITHM | ARCHITECTURE | POLICY | HEURISTIC | DATA_TRANSFORMATION | MODEL_OR_PROMPT_BEHAVIOR | UI_OR_WORKFLOW | INTEGRATION | OBSERVABILITY | TEST_OR_BENCHMARK | NON_ACTIONABLE`. Classification is not a request to generate a Python module.
4. **Gate A**: `PASS | REJECT | DEFER_FOR_EVIDENCE` with recorded reason codes `NO_TECHNICAL_MECHANISM, NO_DEFINED_BEHAVIORAL_DELTA, UNSUPPORTED_CLAIM, DUPLICATE_TEXT_ONLY, ACCIDENTAL_CONCEPT_COMBINATION, NON_OPERATIONAL_GOAL, INVALID_CLASSIFICATION, NO_CONSUMER, NO_MEASURABLE_EFFECT`. Gate A PASS is neither novelty nor implementation approval.
5. **Assimilation + Gate B** compares real current callers, owner, reusable behavior, overlap/conflicts and verification path. Conditional dispositions `IMPLEMENT | MERGE | EXPERIMENT | NO_CHANGE | DEFER | REJECT`; these are historical labels to map to current policy, not autonomous permissions. Production changes require explicit owner/permission, proved gap, `BEFORE → AFTER → EXPECTED OBSERVABLE CHANGE → MEASUREMENT`, and verification plan. EXPERIMENT requires baseline, bounded dataset/workload, metric, failure/cleanup criteria and separate authorization.
6. Preserve evidence-level boundaries `SOURCE CLAIM → DISTILLED INTERPRETATION → ARCHITECTURAL FINDING → IMPLEMENTATION DECISION → VERIFICATION RESULT`.
