### Proposed interface and invariant
- Candidate producers are non-authoritative. An example packet shape is `{node_id, summary, signals, candidate_routes, state_delta}`. Exact fields, types, size/range limits, identity, trust and schema version must be agreed with the existing owner, not assumed. Reject unknown keys, malformed JSON, invalid ranges, forged node identity and unauthorized state_delta. A packet is a **proposal**, never an authorization.
- For invalid generator JSON, historical design proposes **bounded retries or constrained JSON repair followed by strict schema revalidation**. This is an optional, owner-approved recovery path, not silent acceptance: preserve original invalid bytes and repair attempts in permissioned trace; exhaust retry budget to fail closed. Repair cannot forge identity, manufacture evidence, bypass authorization, or conceal malformed input. Test both recoverable formatting errors and irreparable/hostile packets.
- Apply deterministic allowlisted transition validation and existing policy/permission checks *after* candidate generation and *before* any state-changing action. Recheck on fallback or replay; never treat a proposed route as permission.
- Maintain separate raw candidate evidence, validated working packet, bounded stage summary, and canonical decision trace. Retain raw output only under approved access, retention and privacy rules; never inject raw private traces into final model context by default. Record operational metadata (producer, candidate routes, selected/rejected transition, validation failures, authorized state delta, revision/run linkage), **not hidden chain-of-thought**.
- If an existing final synthesizer is a real consumer, its bounded input contract should explicitly include **the original user message, compact stage summaries, selected graph result/route, and selected user-facing surface mode**, subject to privacy and policy checks. Do not treat raw candidate packets as trusted synthesizer instructions or mandate a new synthesizer. Distinguish **user-requested trace mode** (summarized nodes/decisions) from **separately authorized debug mode** (raw node output, rejected paths, route choices and state deltas); raw debug requires explicit permission, redaction, retention and access limits. Neither mode discloses private reasoning.
- Bound stage summaries by relevance and size; preserve contradictory and negative evidence rather than hiding it in compression. Final user-facing factual response must remain direct and independent of internal exploratory labels.
