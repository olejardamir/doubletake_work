## Distinct conditional testable mechanism
**Question:** Does a DT-evolved reusable skill retain utility across sequential tasks and changed contexts, rather than merely exploit an enlarged prompt, remembered trajectory, test leakage or same-task rehearsal? This is a bounded *evaluation contract*, not a request for a new learning controller, skill store, orchestration layer or benchmark framework.

If the CURRENT authorized DT implementation has a persistent skill/strategy producer, consumer and existing independent evaluation seam, identify their exact interfaces, ownership, permissions, current tests, data lineage and immutable revisions. Use existing evaluator and artifact storage only. Hypothesized consumers: governed skill retrieval/application, evolutionary candidate evaluation, and promotion decision; all remain UNKNOWN until source inspection.

For a pre-registered authorized task sequence, freeze task inventory, initial skill/strategy state, source revision, evaluator/oracle, environment and tool/model access, budget, stop criteria and permitted writes. Compare four matched arms: (A) no persistent skill; (B) raw prior trajectories/context only; (C) frozen learned skill; (D) frozen curated skill. For each step record prior-task retention, unseen-task transfer, errors, success, cost/tokens, provenance and actual consumer use. Freeze learned/curated artifacts **before** held-out tests; prevent their modification by evaluation feedback. Run changed-context transfer and two-skill composition with independent success criteria, not merely repeated original tasks. Include held-out in-distribution and out-of-distribution cases, replay/forgetting checks and explicit baseline-versus-treatment comparison. Require a causal witness that the real consumer loaded and applied the exact skill revision; presence in a store or a favorable isolated score is insufficient.

**Positive controls:** a legitimately useful, authorized reusable skill improves held-out task outcome while retaining prior tasks under matched resources; two independently valid skills compose without violating scope. **Negative/falsification controls:** (1) context-only gains disappear when history is removed; (2) same-task memorization fails shifted-context transfer; (3) artifact changed after freeze or test contamination invalidates comparison; (4) raw trajectories equal or outperform curated skill, so no claimed curation gain; (5) new skill improves one task but causes unacceptable forgetting elsewhere; (6) unauthorized or wrong-revision skill cannot be consumed; (7) composition creates conflicting effects or breaks governance; (8) missing oracle, unreconciled benchmark task/domain inventory, unavailable execution service or unmatched model/budget/stop criteria yields INCONCLUSIVE/NO_AUTHORIZED_FIXTURE rather than PASS; (9) isolated mock scores without production-consumer receipt cannot be promoted. Record failures and no-improvement evidence, not only positive cases.
