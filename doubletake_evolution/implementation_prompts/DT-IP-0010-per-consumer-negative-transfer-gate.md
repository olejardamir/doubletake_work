## Distinct objective and bounded mechanism
Do **not** create another SkillGym, general evaluator, generic A/B harness, skill distiller, controller, or automatic propagation pipeline. The sole potentially novel behavior is preserving a **per-authorized-consumer × per-domain transfer/negative-effect matrix**, including held-out utility, regressions, safety invariants and costs, instead of collapsing distinct outcomes into a single global `skill assimilated` claim. A consumer-specific selective propagation policy is **future, separately owner-authorized**, only if unseen-task evidence shows an improvement over the existing policy without cost, safety, authorization or no-loss regression.

**Prerequisite gates:** an existing independently evidenced 7.8.1-style run/mission-revision/actual-consumption receipt; a qualified 7.5-style source-derived knowledge item K; an existing authorized 7.8.3-style evaluator and disposable fixture; an identified actual consumer and owner. If missing, return `CONSUMER_UNOBSERVED`, `NO_QUALIFIED_K`, `NO_AUTHORIZED_EVALUATOR`, or `NO_CURRENT_CONSUMER`; do not construct replacements or bypass B1. A second consumer is optional and allowed only when already authorized and available.

## Future authorized evaluation contract (no execution now)
1. **OUTWARD:** freeze K's public source, version, rights and provenance; predeclare independently scored held-out K-dependent tasks and pre-K performance/cost for each existing authorized consumer. Freeze model/harness/evaluator versions, input tasks, budgets and seeds when supported.
2. **INWARD:** only the existing owner approves or denies K through an existing governed channel. Bind decision, K version, actual run and consumer receipt. No automatic source-to-code mutation.
3. **GROUND:** independently observe disposable paired runs: A = no K baseline; B = accepted K; C = reversible K withholding; D = wrong-domain/irrelevant K; E = source-equivalent rephrasing. Keep all other factors matched; repeat and capture per-consumer/domain held-out success, process invariants, negative effects, latency/cost, and later ordinary-task reuse.
4. **Acceptance:** B>A on a predeclared K-dependent held-out behavior, appropriate loss/change of gain under C, no spurious D gain, safe E behavior, no safety/authority regression, independent repeat and demonstrated reuse. Preserve **each** negative transfer rather than averaging it away. If A already passes: `ALREADY_PRESENT`; B fails to improve: `NO_GAIN`; B regresses: `NEGATIVE_TRANSFER`; only synthetic injection passes: `FIXTURE_ONLY`. If existing SkillGym/7.8.3 already provides a sufficient per-consumer matrix, `ALREADY_PRESENT` and no code change.
5. **Negative tests:** one consumer improves while another worsens; K has wrong domain; withheld K still apparently drives a gain; rephrasing changes safety outcomes; source/version/receipt mismatches; stale or self-reported-only receipts; missing independent evaluator; no qualified K; no authorized owner; high-risk instruction embedded in K; unauthorized model/host access; protected history mutation; higher cost/latency without net utility; unobserved reuse. All must fail closed or remain UNKNOWN, never count as proof of assimilation.
