### Required behavior, where an actual current gap is verified
1. Reuse the **existing unified DT catalog and resolver** for MCP tools, native tools, skills, services and callable specialists. Do not introduce a parallel MCP-only router, registry, vector store or dependency without independently demonstrating necessity.
2. Use pipeline: provider adapter → normalized **provider-qualified canonical descriptor** → structural and **hard permission/approval/scope** eligibility → independent lexical and semantic retrieval pools → deterministic identity deduplication/fusion → contextual rerank → bounded top-K/token/schema projection → **immediate** current provider/schema/authority/permission revalidation → governed invocation → sanitized telemetry. Semantic ranking never grants execution authority; only exactly projected/current canonical IDs are executable.
3. Descriptor carries stable provider-qualified ID and aliases, exact schema hash/revision, provider revision/health/availability, required permissions/approval, task/worker compatibility, cost/latency and indexed metadata. Ambiguous same-named tools stay distinct by provider identity. Exact live schema is used at invocation, not abbreviated indexed metadata.
4. Provider add/remove/schema change, health change or policy/permission revocation invalidates affected cache/index/projection. A cached grant cannot survive a revoked policy. Keep feedback bounded and avoid unverified long-lived learned authority.
5. Deterministic lexical-only fallback when semantic retrieval is unavailable, **subject to identical hard authority checks**. No-candidate, guessed/unprojected ID, malformed args/schema and stale-projection routes fail closed. Bounded cold-start feedback and stable selection; indexes are only candidate retrieval, not approval.
6. Preserve current DT owners and compatibility; benchmark behavior before adding resources or migrations. **Potential B7 contribution (not closure):** the source specifically identifies governed consumer-selection and no-loss policy revalidation as potentially relevant. Where a real current consumer exists, test whether a capability selected for that consumer remains bound to its canonical provider identity, projection, live policy and schema through invocation, including policy revocation after selection and a no-loss fallback/rejection path. These are hypotheses requiring current-DT owner and test evidence; a passing isolated projection test does **not** establish end-to-end B7 consumer-selection closure. Do not claim this resolves historical B1 protected-history disposition, full B7, an autonomous natural cycle or current implementation parity merely from the source.
