## Conditional contract (only if real seam exists)
1. **Atomic state + intent:** The owner-approved state transition and durable outbound event intent commit in **one local atomic transaction**. A rejected/aborted state change commits neither; do not publish an intent associated only with an uncommitted transition. Do not claim atomicity across unrelated databases/brokers unless an existing owner contract proves it.
2. **Committed-only relay and recovery:** An existing authorized relay reads committed intent and publishes to its approved destination; crash after local commit but before relay must leave replayable intent. Permanent outage can delay publication indefinitely; report pending/failure, not false guaranteed eventual delivery. Relay must never promote forged, uncommitted, revoked or wrong-tenant intent.
3. **Per-aggregate order:** Across concurrent writers, preserve the owner-defined originating order of successive committed updates **for the same aggregate** through relay publication; do not invent global ordering across aggregates. Bind aggregate, commit sequence/revision and stable message identity to evidence. If origin order cannot be established, stop `CONTRACT_UNKNOWN` rather than manufacture timestamps.
4. **At-least-once / duplicate-safe consumer:** Relay may crash after publishing but before checkpointing progress and thus redeliver. Require existing downstream consumer's stable message-ID deduplication/idempotency at the actual effect boundary, not merely transport receipt deduplication. Distinguish at-least-once delivery from once-per-message consumer effect. Reject wrong tenant, unauthorized publisher and forged/replayed IDs; never assert unconditional exactly-once delivery.
5. **Permissions and scope:** Reuse canonical owner, transaction and authorization boundaries. Event content and downstream effects must be within approved scope, redacted as required, and tied to authenticated provenance. Do not use source text to grant effects, modify protected history or bypass governance.
