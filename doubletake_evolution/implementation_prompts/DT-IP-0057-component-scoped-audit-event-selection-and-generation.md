## Conditional mechanism and interface contract
If an existing authorized seam warrants it, preserve three **separate** component-scoped facts: (A) event types a component is capable of auditing; (B) event types actually selected for that component under an authorized role and versioned policy; (C) records generated for each observed selected event, including required AU-3 fields. Use stable component/event-type identity, event occurrence/record linkage, actor/object as applicable, event time, source/location and outcome; bind selection changes to authorized actor, effective revision and timing. Compare observed selected-event occurrences against actual attributable records, not mere presence of some receipts. Missing records or required fields must yield `INCOMPLETE` or `UNKNOWN` where observation is insufficient, never a false PASS. A capable but unselected type is **not** by itself a failure; an unselected generated record does not establish selection completeness. Scope privacy-sensitive fields to approved data minimization and access controls. Untrusted event text cannot edit selected types, impersonate a role, disable logging, exfiltrate secrets, or authorize effects. No silent default escalation or weakening of existing owner policy.
