## Distinct bounded behavior and candidate consumer
At an **already existing** owner-approved disposable Python patch-test seam, check whether a specific safety property assertion would fail on a near-miss behavioral mutant. This is **assertion sensitivity**, not proof that a patch was applied, a natural mission consumed it, B1 history is valid, or knowledge was assimilated. Hypothesized owner: existing patch-test/Director owner; actual identity, contract, source/test parity, permissions and consumer UNKNOWN. Unlike DT-IP-0016 (filesystem check/use race), DT-IP-0018 (termination trace semantics) and DT-IP-0011 (acknowledged history oracle), this tests the sensitivity of the *current focused assertions* to deliberately introduced one-change mutants across several safety properties, with equivalent-mutant and infrastructure-error controls.

## Frozen evaluation, interfaces and negative tests
1. Freeze exact private source/test revisions, existing owner property assertion, canonical command, resource/time budget, fixture identity and independent observation plan *before* results. Select **4–6 non-equivalent one-change behavioral mutants** from applicable properties: (a) stale evidence accepted, (b) failed durable acknowledgement accepted as success, (c) fail-closed decision bypassed, (d) nonterminal event accepted as completed. Never force irrelevant properties onto a consumer.
2. On the same disposable fixture and matched total budget, run unchanged baseline and each mutant against **A** existing assertions; compare **B** owner-approved improved property-specific assertions; include an intentionally equivalent/irrelevant mutant (must not count as fault), known-fault positive control, unrelated passing control, and line coverage as a **noncausal** comparator. Avoid changing production code to plant mutants.
3. A mutant is *killed* only when a **property-specific assertion** detects the targeted wrong behavior. Syntax errors, import failures, environment failures, unrelated exceptions, timeouts and absent execution logs do **not** count as kills. Preserve independent command, version, exit, logs/digests and resource-cost receipts; verify unrelated behavior remains intact.
4. Success requires baseline passes, at least one real non-equivalent safety mutant survives A but is killed by B within frozen budget, no false completion/authority, and independently observed results. Otherwise classify `ALREADY_PRESENT`, `NO_DELTA`, `INDETERMINATE`, `NO_AUTHORIZED_FIXTURE` or `EXECUTION_UNVERIFIED`. Toy-only outcomes are `METHOD_ONLY`, not DT parity, Ground, applied patch or natural mission proof.
