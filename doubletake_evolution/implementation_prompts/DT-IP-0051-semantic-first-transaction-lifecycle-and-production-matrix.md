## Required conditional lifecycle
1. **Automatic governed entry:** A normal write-capable user request establishes its *own* request/run/workspace/epoch-bound semantic transaction before any effectful dispatch; a read-only capability may take a genuinely enforced read-only path. An ambiguous natural-language prompt never converts a write-capable runtime into read-only authority. An unrelated old transaction cannot be reused.
2. **Model before mutation:** Distinguish deterministic code facts from inferred, unknown, unresolved and conflicted semantic claims. Construct current model, governed architectural choice (prompt-only, prompt-driven or deterministic code), proposed target and exact change/overlay digest. A legitimate no-change/rejection must produce zero mutation; no new parallel owner is implied.
3. **Exact authorization:** Bind transaction to semantic current/target, accepted implementation and semantic baselines, target digest, exact write set, policy, conflict identity, run/request/workspace/epoch and revocation state. Recheck at actual effect time against stale backend, revision drift, TOCTOU, replay and wrong-scope effects. Enforce for UI, API, CLI, MCP, agent/subagent, shell/Git/subprocess, Harvest and autonomous repair; when external edits cannot be prevented, detect drift and quarantine. Govern direct canonical semantic-file writes as effects too.
4. **Semantic truth and lifecycle:** Bootstrap and incrementally refresh only affected scope; retain stable semantic identities across behavior-preserving refactors; handle deletion, replacement, supersession, ownership and relationships. Keep canonical history isolated from tests, dry runs and derived indexes. Classify implementation-ahead, semantic-ahead, both-diverged, partial implementation and stale-base from recorded common base; overlapping concurrent changes cannot silently choose a winner. Never infer `SYNCED` from partial enrichment, guessed API existence, stale indexes or mere `EVIDENCE_GATHERED`.
5. **Completion and recovery:** Provider/tool success is not task success. Require actual authorized implementation evidence, real verification, semantic enrichment, reconciliation, atomic canonical promotion and independently observed final state. Failed verification, missing provenance, stale target, wrong conflict or incomplete semantic generation deny terminal success. Crash/restart must resume or roll back durably; safe/recovery mode cannot become a mutation bypass. Independent re-assessment after restart must confirm state, not merely a stored status label.
