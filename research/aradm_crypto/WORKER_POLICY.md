# ARADM Crypto Research — Hourly Worker Contract

**Storage:** \`olejardamir/doubletake_work\`, branch \`main\`, directory \`research/aradm_crypto/\`. **Execution:** ChatGPT scheduled task, never GitHub Actions. **Scope:** Public Binance spot-listing event research and **paper-only** action research; no exchange orders, no trading-account changes, no circumvention of residency restrictions.

## Immutable inputs and output lineage
- Starting Reality model: \`versions/ARADM_M_v0001.md\` (copied verbatim from the earlier v1 research specification).
- Starting Advantage model: \`versions/ARADM_XM_v0001.md\` (copied verbatim from the earlier v1 research specification).
- \`LATEST.md\` is the authoritative pointer to the latest successfully committed **pair** of model files. Always read it first, then fetch the exact two referenced files; preserve their formulas, caveats, evidence and mathematical assumptions unless a verified change replaces them.
- Each completed hourly run writes two **new full Markdown snapshots**: \`versions/ARADM_M_vNNNN.md\` and \`versions/ARADM_XM_vNNNN.md\` (same incrementing version number), then updates \`LATEST.md\` only after both snapshots have been remotely fetched and verified. Do not silently truncate the old documents. Each snapshot must include parent path, as-of UTC time, sources and hashes where available, changes, negative results and the full revised model.
- If a run has no defensible improvement, still record the attempt in a new versioned pair with a clear \`NO MODEL PROMOTION / EVIDENCE UNCHANGED\` entry. Never falsely claim better accuracy, profit or successful upload.
- Do not touch \`DT\` code, other worker directories, GitHub Actions, or existing unrelated files.
- Writes are sequential with content-SHA preconditions. On stale state, refetch \`LATEST.md\`, reconcile and retry at most once; never overwrite new work.

## Research loop — one bounded pass each run

1. **Recover state**: fetch \`LATEST.md\`, both corresponding model versions, latest recorded scores and any unresolved validation failures. Confirm remote GitHub write access; if missing, report the blockage instead of claiming a commit.
2. **Discover events**: query official Binance spot-listing announcements and scheduled revisions; list previously missed historical events and any newly announced spot pairs. Distinguish the public announcement's original publication, amendments, any earlier public mentions, actual first spot trade, and decision time. Deduplicate by (asset, venue, market type, quote asset, listing event). Do not mistake Binance Alpha, futures premarket, or a re-listing for a first spot listing. Record explicitly if no new listing.
3. **Retrieve market data**: use official Binance read-only market APIs for available 1m/5m candles and spot metadata, plus independently timestamped earlier public information. Store links, observed timestamps, missing data and market eligibility. Exclude impossible/invalid symbols from return metrics; segregate stable/reference tokens. Beware dataset selection bias and token delisting survivorship.
4. **Update Reality Model (ARADM-M)**: forecast full *conditional price path* after decision time, including probability/magnitude of surge, time-to-peak, time above thresholds, reversal hazard, downside excursion, volatility/liquidity regime, and uncertainty. Separate early announcement from tradable entry. Only use signals verifiably known at the forecast time. Censor trajectories whose observations are incomplete.
5. **Update Advantage Model (ARADM-XM)**: use Reality model forecasts and feasibility gates to choose research, watch, skip, paper entry, paper hold, or paper exit. **No fixed 24-hour holding rule.** Model an *adaptive optimal stopping time*, e.g. \`tau* = inf{t >= entry : adjusted exit value >= conditional continuation value OR a hard risk/eligibility condition fires}\`, allowing hold times of minutes, hours, days, or longer if evidence supports it. Predict **how long to remain in a paper position**, update as new observations arrive, and consider time-to-peak and reversal risk without looking into the future. Compare candidate exits on a time grid from 5m through at least 7d when history exists; use terminal truncation only as an explicit **research observation horizon**, not the user's required exit deadline.
6. **Execution realism**: distinguish high/low *touch* from feasible entry/exit, enforce causal latency and order-book availability, maker/taker fees, spread, slippage, market impact, minimum orders, partial fills, outages, tax/eligibility constraints where relevant. Run 0.4%, 1%, and 2% friction sensitivity, and document when data cannot support fill conclusions. **Paper only**; never place orders or recommend circumventing restrictions.
7. **Falsifiable evaluation**: anchored chronological walk-forward splits, purge overlapping outcome windows, grouped same-day or related listings, strictly matured labels, frozen forecast timestamps and held-out test periods. Compare against prior version, always-skip, simple fixed-hold baseline over multiple horizons, and random eligible decisions; report per-trade and portfolio returns, median, concentration/outlier sensitivity, max drawdown, downside CVaR, calibration and statistically meaningful uncertainty. Include negative results and no-trade rate. Do not promote a rule because it looks good on cases used to tune it; distinguish hypothesis generation from fresh validation.
8. **Commit two full updated Markdown snapshots** and then update \`LATEST.md\` with the exact new paths, UTC time, evidence count, outcomes, validation status and links. If no new data or validation, keep model mathematics intact, add a short reproducible research log, and mark research iteration only. Verify remote reads of both files and pointer; state any partial write explicitly. Summarize material changes and blockers in the scheduled result.

## Boundaries and quality gates
- Success is **improved out-of-sample calibration and risk-adjusted *paper* decision utility**, not a mandatory profit claim. Abstain when no defensible trading edge exists.
- The worker cannot change the market. Local model changes must be recorded as proposed math and tested evidence, not as proven causal effects.
- Never claim causality from before/after association; align announcements to time-zone-correct actual trading times.
- No leakage: changes published at \`t+1\` cannot feature in a forecast timestamped \`t\`.
- Never treat success at an intrabar extreme as a realistically filled trade.
- Never silently shift a fixed 24h exit into reported dynamic performance; keep 24h as **one baseline only**.
- If necessary tools are unavailable on a run, save the blocker in a Markdown run entry if GitHub is writable; do not fabricate analysis or commits.
